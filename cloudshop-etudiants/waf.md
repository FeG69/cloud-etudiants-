### Matrice d'évaluation Well-Architected Framework (WAF) — CloudShop

| Pilier WAF | Nos choix d'architecture (Azure) | Risques résiduels | Impact coût |
| :--- | :--- | :--- | :--- |
| **Fiabilité** | - **Azure App Service** avec Auto-scaling pour absorber automatiquement les pics des soldes ($\times$5).<br>- **Azure SQL Database (Serverless)** avec sauvegardes automatiques toutes les 5 à 15 min (RPO < 1h).<br>- Stockage des images sur **Blob Storage ZRS** (Zone Redundant) pour une haute disponibilité locale. | - En cas de panne complète de la région Azure (très rare), l'application sera indisponible le temps de restaurer la base (RTO de 4h respecté). | - **Faible** : Facturation à l'usage réel. L'Auto-scaling n'augmente le budget que pendant les quelques jours de soldes. |
| **Sécurité** | - Hébergement exclusif en **Région UE** (ex: France Central / North Europe) pour conformité stricte **RGPD**.<br>- Isolation des flux sensibles (backoffice/API) via des règles d'accès réseau.<br>- Secrets et chaînes de connexion BDD stockés de manière sécurisée dans **Azure Key Vault**. | - Risque d'attaques par déni de service (DDoS) ou applicatives si les règles de sécurité par défaut du CDN/Front Door ne sont pas régulièrement durcies. | - **Très Faible** : Azure Key Vault et le CDN de base coûtent moins de 2 €/mois pour ce volume de trafic. |
| **Optimisation des coûts** | - Approche **100% PaaS / Serverless** : aucun coût de compute fixe lorsque le trafic est quasi nul la nuit.<br>- Configuration de l'**Auto-pause** (1h) sur la base de données de Dev.<br>- Pas de machines virtuelles (VM) à provisionner inutilement. | - Si un bug applicatif fait tourner l'API en boucle la nuit, la base de Dev ne passera pas en auto-pause, générant un léger surcoût sur les vCores. | - **Optimal** : Garantit le respect strict des budgets très serrés (Dev < 5 €/mois, Prod < 60 €/mois). |
| **Excellence opérationnelle** | - Architecture **Zéro VM à administrer** : aucune mise à jour d'OS ou de patch de sécurité système à la charge de l'équipe.<br>- Supervision automatique via **Azure Application Insights** pour centraliser les logs et remonter les erreurs de l'API. | - **Aucune astreinte** : si l'application plante un dimanche à cause d'un bug majeur, elle le restera jusqu'au lundi matin (sauf auto-healing Azure). | - **Nul** : Le niveau gratuit (*Free Tier*) d'Application Insights est largement suffisant pour 2 000 visites/jour. |
| **Efficacité des performances** | - Mise en cache agressive du catalogue d'artisanat (fichiers statiques et images) via le **CDN Azure**.<br>- Ajustement dynamique des ressources de la BDD (jusqu'à 2 ou 4 vCores) lors des fortes sollicitations de l'API. | - **Cold Start** : lors du premier visiteur de la journée ou après une mise en pause, l'application peut mettre quelques secondes à répondre (réveil de l'instance). | - **Maîtrisé** : Évite de surdimensionner et de payer pour des performances maximales permanentes. |
